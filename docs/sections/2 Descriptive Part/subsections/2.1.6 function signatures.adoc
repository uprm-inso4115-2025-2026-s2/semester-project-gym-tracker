==== 2.1.6 Function Signatures

Notation uses the form:

functionName : InputTypes -> OutputTypes

Where multiple outputs indicate updated state and produced results.

===== Core Recording Functions

[.added]#recordWorkout :#
[.added]#    GymGoer >< Workout >< CalendarDay >< Duration >< WorkoutNotes#
[.added]#    -> GymGoer >< WorkoutSession#

[.added]#Records a Workout Session for a GymGoer and returns the updated GymGoer together with the newly created WorkoutSession. The GymGoer is in the result because recording a workout modifies the GymGoer's WorkoutHistory; the WorkoutSession exists within that history and is not accessible independently. This signature is consistent with the definition in Section 2.1.2.#

[.added]#updateWorkoutSession :#
[.added]#    WorkoutHistory >< WorkoutSession >< Activity >< Duration >< CalendarDay >< Notes#
[.added]#    -> WorkoutHistory >< WorkoutSession#

[.added]#Modifies an existing recorded Workout Session within the WorkoutHistory.#

deleteWorkoutSession :
    WorkoutHistory >< WorkoutSession
    -> WorkoutHistory

Removes a recorded Workout Session from the WorkoutHistory.

[.added]#retrieveWorkoutHistory :
    GymGoer
    -> WorkoutHistory#

#Determines the WorkoutHistory associated with a GymGoer. This is the entry point through which all Workout Session retrieval happens. A Workout Session is only accessible through the GymGoer whose history contains it.#

[.added]#getSessionsInRange :#
[.added]#    WorkoutHistory >< CalendarDay >< CalendarDay#
[.added]#    -> [WorkoutSession]#

[.added]#Returns all Workout Sessions in the WorkoutHistory whose Calendar Day falls within the specified range. This function makes explicit how two sessions can be selected for comparison — a caller first retrieves the WorkoutHistory, then selects sessions from it using this function.#

[.added]#getLastSessionByActivity :#
[.added]#    WorkoutHistory >< Activity#
[.added]#    -> WorkoutSession#

[.added]#Returns the most recent Workout Session in the WorkoutHistory for a given Activity type. This expresses a common query (e.g., "last bench press session") that is otherwise implied but not defined.#


===== Goal Management Functions

setWeeklyGoal :
    WorkoutHistory >< GoalTargetCount
    -> WorkoutHistory >< Goal

Creates a new weekly goal and stores it in the history.

updateGoal :
    WorkoutHistory >< Goal >< GoalTargetCount
    -> WorkoutHistory >< Goal

Modifies an existing goal.

removeGoal :
    WorkoutHistory >< Goal
    -> WorkoutHistory

Deletes a goal from the history.

===== Evaluation and Analysis Functions

computeStreak :
    WorkoutHistory
    -> StreakLength

Determines the current number of consecutive attendance days.

evaluateWeeklyGoal :
    WorkoutHistory >< Goal >< Week
    -> GoalResult

Determines whether the goal for the specified week has been achieved.

generateWeeklySummary :
    WorkoutHistory >< Goal >< Week
    -> WeeklySummary

Produces an overview of attendance, missed days, and goal status.

compareSessions :
    WorkoutSession >< WorkoutSession
    -> SessionComparison

Evaluates differences between two sessions, such as Duration or activity type. [.added]#To obtain two sessions for comparison, the caller first invokes retrieveWorkoutHistory to obtain the GymGoer's WorkoutHistory, then invokes getSessionsInRange or getLastSessionByActivity to select the two sessions.#

evaluateConsistency :
    WorkoutHistory >< TimePeriod
    -> ConsistencyMeasure

Determines the regularity of workouts across a period of time.

===== [.added]#Consistency Note#

[.added]#In this section, the history input is intentionally modeled as
WorkoutHistory across the domain functions. Attendance Days and Streak
are derived from the WorkoutSessions contained in that WorkoutHistory,
rather than being supplied as a separate primary collection. The
retrieveWorkoutHistory function makes explicit how the relevant
WorkoutSessions are obtained for a given GymGoer.#

[.added]#GoalTargetCount is the positive integer count carried by Goal
management functions, while GoalResult is the value returned by goal
evaluation functions.#

[.added]#The type name Duration is used throughout all function signatures in place of the earlier Minutes. Duration is defined in Section 2.1.2 as the domain-level name for elapsed session time, expressed in minutes. The rename ensures that the function signature language matches the domain terminology rather than an implementation unit.#
