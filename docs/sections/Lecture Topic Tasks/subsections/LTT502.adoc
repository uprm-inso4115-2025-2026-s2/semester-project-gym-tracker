== 2. Requirement Prescription Units


The following requirement prescription units are extracted from the proposed feature:

- The system shall store login dates persistently
- The streak shall increment only once per calendar day
- The streak shall reset if a login day is missed
- Users may create next-day workout commitments
- Achievements shall unlock automatically
- Rest Day Tokens shall preserve streaks under defined conditions
- Duplicate achievements shall not be possible
- Backend logic shall validate unlocking rules

These units are classified and analyzed in later sections.

== 5. Elicitation Process

According to the lecture, elicitation includes:
- stakeholder interviews
- questionnaires
- exploratory discussions
- recording requirements 

=== Example Elicitation Questions

==== Entity Questions

- What user data should be tracked for streaks?
- Should Rest Day Tokens be visible to users?
- What achievement types should exist?

==== Function Questions

- How should streak increments behave?
- How should missed days affect streaks?
- How should achievements unlock?

==== Behaviour Questions

- What sequence occurs after login?
- How should the system react when a streak would reset?
- How should commitment completion affect achievements?

== 7. Potential Requirement Issues

=== Incompleteness

Possible missing requirements:
- No timezone handling defined
- No offline login behavior specified
- No limit defined for achievement quantity

---

=== Conflicts

Potential stakeholder conflict:
- Competitive users may want harsher streak penalties
- Casual users may prefer flexible streak systems

Possible solution:
- Allow configurable streak preferences

---

=== Ambiguity

Example:
- "Daily login" may be interpreted differently across timezones

Possible improvement:
- Define login-day boundaries explicitly

---

== 8. Requirement Quality Improvements

Recommended improvements include:

- Define timezone policies
- Clarify streak reset conditions
- Specify token expiration rules
- Add validation constraints
- Define achievement threshold values explicitly
